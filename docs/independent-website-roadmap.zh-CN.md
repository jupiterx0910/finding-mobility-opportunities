# Opportunity Radar 独立网站产品路线图

> 状态：规划基线 v1.0  
> 目标：把现有的机会判断框架与静态 demo，演进为持续采集证据、生成研究、保留历史判断并接受现实检验的独立网站。  
> 原则：先交付可验证的最小产品，再增加自动化；不把“AI生成了报告”误当成“机会已经被验证”。

## 1. 产品定义

Opportunity Radar 不是新闻聚合器、行业热榜或自动生成商业计划书的工具。它是一个以证据为中心的创业机会研究系统，帮助用户回答：

1. 哪些结构性变化正在发生？
2. 这些变化会重新分配哪些利润池？
3. 谁是受益者、使用者、决策者和真正付款者？
4. 新进入者能从产业链的哪个具体位置切入？
5. 哪些证据已核实，哪些只是推断或假设？
6. 如何用低成本实验验证付款、复购和单位经济？
7. 什么新证据会让我们升级、降级或终止判断？

## 2. 当前基线与边界

现有仓库已具备：
- Agent Skill 与系统化机会判断框架；
- `radar/opportunities.json` 机器可读机会数据；
- `demo/` 静态交互界面；
- 资本热度、付款、留存、贡献利润、证据覆盖、反方论证和失败案例等判断维度；
- GitHub Actions 中的基础验证工作流。

当前静态 demo 不等于实时研究网站。未完成并验证之前，不得声称已有持续数据采集、自动研究流水线、数据库服务或正式生产部署。

## 3. 产品原则

### 3.1 事实、推断、假设分层

每个研究结论必须归入以下一种类型：
- **Verified Fact**：有可追溯来源、发布日期和可核对内容的事实；
- **Evidence-backed Inference**：由多个事实支持，但仍存在替代解释的推断；
- **Hypothesis**：尚未得到足够证据支持、需要验证的假设；
- **Market-validated**：有真实客户行为证据支持，需说明验证范围、时间与样本限制。

“媒体报道很多”“资本融资活跃”“政策鼓励”均不能单独证明创业机会成立。

### 3.2 机会评分与证据置信度分离

每条机会至少分别呈现：
- 结构性变化强度；
- 真实付款与复购证据；
- 新进入者可进入性；
- 利润捕获与竞争壁垒；
- 监管与执行风险；
- 资本热度及其与客户需求的背离；
- 证据覆盖率、来源质量、关键未知项；
- 窗口阶段与建议验证动作。

不得用单一总分掩盖证据不足。缺乏关键付款或留存证据时，即使行业热度很高，也不能直接给出 START。

### 3.3 反方研究是必需项

每条重点机会必须回答：
- 为什么现在仍然存在机会？
- 为什么更强的公司尚未解决？
- 利润可能被平台、品牌方、渠道、供应商或监管方拿走吗？
- 哪个关键假设一旦失败，就应停止投入？
- 有什么证据会推翻当前结论？

### 3.4 数据可追溯、历史不可静默改写

保存来源、抓取/录入时间、发布日期、原文摘要、去重标识、研究版本、模型/提示词版本、评分变更和变更原因。旧判断通过新版本修正，不覆盖历史记录。

## 4. MVP 范围

### P0：可上线的研究型网站

1. **首页 / 机会雷达**：展示近期值得关注的结构性变化和机会，支持按领域、窗口阶段、证据置信度、资本热度筛选。
2. **机会详情页**：每条机会包含具体切入业务、目标付款者、利润池逻辑、关键证据、反方论证、未知项、评分和更新时间。
3. **证据来源页/区块**：来源名称、原始链接、发布日期、获取日期、支持的具体结论和可信度。
4. **历史变化**：显示评分、证据与结论的变动，而不是只展示当前结论。
5. **验证任务**：为机会提供 30–60 天内可执行的访谈、报价、付费试单或单位经济验证。
6. **维护机制**：数据校验、失败日志、重复数据处理、定时任务状态与人工复核入口。

### P1：持续发现系统

- 采集公开政策公告、企业公告、公开融资信息、招聘信号、专利/技术发布、贸易与产业数据、行业协会信息及可信媒体；
- 每条信号记录来源、时间、主题、地区、主体、证据类型和抓取状态；
- 对同一事件去重，并将相关信号聚合到结构性变化；
- AI 生成候选机会和反方解释，人工/规则复核后才发布；
- 失败的采集任务可重试，重要异常可告警；
- 每次运行生成可审计的任务日志。

### P2：学习与反馈

- 记录用户或研究者实际执行的验证动作；
- 记录访谈、报价、试单、付款、毛利、复购、回款周期等结果；
- 将预测与后续结果对照，分析不同评分维度是否有区分能力；
- 公开展示机会被升级、降级或终止的原因；
- 不把未验证的点击、收藏或用户兴趣当成商业验证。

## 5. 推荐的技术路径

采用可替换、低运维的模块化架构，不在早期自训模型。

- **前端**：Next.js + TypeScript；先完成响应式研究界面、列表、详情、筛选和历史记录。
- **数据库**：PostgreSQL；可使用 Neon 等托管服务。核心实体包括 `sources`、`signals`、`opportunities`、`evidence`、`score_snapshots`、`experiments`、`experiment_results`、`pipeline_runs`。
- **采集调度**：初期用 GitHub Actions 定时任务或托管调度器；需考虑频率限制、源站条款、重试、超时与数据新鲜度。
- **研究引擎**：可替换的模型适配层；输出必须符合 schema，并要求引用已收集的证据 ID，不允许模型凭空生成来源。
- **质量控制**：字段校验、来源链接检查、重复检测、事实/推断/假设标签、人工发布门槛。
- **部署**：前端托管平台 + 托管 PostgreSQL + GitHub Actions。正式上线前单独验证环境变量、权限、备份和恢复。

不要在 MVP 阶段把系统绑死在某一家模型或某个数据供应商上。

## 7. 发布门槛

机会进入公开列表前必须通过以下检查：
- 至少有一个可核查的核心来源；
- 核心结论标记为事实、推断或假设；
- 明确地理范围与时间范围；
- 明确谁可能付款，而非只写受益用户；
- 有具体进入楔子，而非只写行业名称；
- 有至少一个强反方解释；
- 明确最关键的未知项和可证伪条件；
- 有一个低成本、有限时间的下一步验证动作；
- 若缺乏付款/复购证据，明确标记为“未验证”，不得包装成已验证机会。

## 8. 首批研究范围

首期聚焦“中国市场 × 全球技术/供应链变化”，不追求覆盖所有行业。建议从以下领域做对照研究：
- AI 应用与垂直工作流；
- 跨境贸易与海外本地化服务；
- 先进制造、工业服务与机器人后市场；
- 能源转型的安装、运维、检测和服务链；
- 老龄化相关的非医疗服务与效率改造；
- 传统行业因成本、渠道、制度或供应链变化产生的新切口。

每个领域同时寻找“热门窗口”和“被忽视窗口”，并记录不值得进入的反例。以上只是研究范围，不代表这些领域已被证明适合创业。

## 9. 交付顺序与验收

### Milestone 1 — 产品规格与数据契约
- 完成产品路线图；
- 定义核心实体、字段、证据分类与发布门槛；
- 明确静态 demo 与生产系统之间的差距。

**验收**：开发者能根据文档建立一致的数据结构，不需要自行猜测字段含义。

### Milestone 2 — 真实网站骨架
- 完成首页、机会列表、机会详情、证据区块与历史评分展示；
- 使用标注清楚的示例数据；
- 移动端可用、页面有空状态和错误状态。

**验收**：陌生用户能在 2 分钟内理解一个机会的判断依据、关键风险和下一步验证动作。

### Milestone 3 — 数据库与管理入口
- 接入 PostgreSQL；
- 支持导入/更新机会、保存评分快照和证据；
- 不允许未经校验的数据直接公开发布。

**验收**：修改一次机会后可看到历史记录，来源与评分均可追溯。

### Milestone 4 — 第一条自动采集流水线
- 先选 3–5 个稳定、可合法访问的公开来源；
- 做抓取、解析、去重、校验和日志；
- 先自动收集信号，不自动发布最终机会结论。

**验收**：连续运行 7 天，能够查看成功率、重复率、失败原因和数据新鲜度。

### Milestone 5 — AI 研究与人工复核
- 由多个信号提出候选机会；
- 生成证据矩阵、反方论证和验证方案；
- 经过发布门槛后才公开。

**验收**：随机抽查候选报告，每个核心事实都能追溯到来源；不支持的结论会被标记为假设或删除。

### Milestone 6 — 反馈与校准
- 记录验证实验与真实商业结果；
- 定期评估机会判断质量；
- 记录升级、降级和终止的依据。

**验收**：系统不仅能新增机会，还能基于新证据纠正过去判断。

## 10. 核心产品指标

不以页面浏览量或每天生成的机会数量作为首要指标。

优先追踪：
- **Evidence Traceability**：核心事实可追溯率；
- **Freshness**：有效信号的更新延迟；
- **Signal Precision**：人工抽查后有价值的信号占比；
- **Opportunity Conversion**：进入验证阶段的机会占比；
- **Paid Validation Rate**：获得真实付费验证的机会占比；
- **Kill Speed**：发现关键假设不成立后停止投入所需时间；
- **Calibration Quality**：不同置信度等级与后续结果是否一致；
- **Decision Usefulness**：研究是否促成具体决策，而非只增加阅读量。

## 11. 明确不做的事

- 不声称 AI 能可靠预测下一个“跨境电商”或“移动支付”；
- 不把融资额、媒体热度或政策支持直接等同于创业机会；
- 不生成没有来源的精确市场规模和增长率；
- 不把行业增长等同于创业者可以捕获利润；
- 不在没有授权和合规依据时大规模抓取受限制数据；
- 不在没有真实客户证据时把机会标成“已验证”；
- 不通过覆盖更多行业来掩盖研究深度不足。

## 12. 当前最优下一步

先做 **Milestone 1 + Milestone 2**：确定数据契约，并将现有静态 demo 演进为清晰的研究型网站骨架。完成并验收后，再接数据库和自动采集。这样能先验证用户是否能从页面读懂、比较和行动，再投入自动化成本。
